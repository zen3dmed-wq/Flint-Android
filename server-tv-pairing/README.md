# Flint — добавление Android TV по QR через интернет

Этот пакет **подготовлен для разработчика, на flintmain.ru не установлен**.
Он обслуживает только новые адреса `/api/v1/devices/pairing/*`. Страницы сайта,
действующие методы входа, оплаты и база данных остаются за существующим сервером.
Клиентская сторона — Flint Android и Android TV **8.11.8 / 3008**.

## Как работает для пользователя

1. На ТВ нажать «Добавить с помощью QR».
2. На телефоне открыть Flint, войти в свой аккаунт любым доступным способом
   (почта подходит, Telegram не обязателен), затем QR-код → Камера.
3. Отсканировать экран ТВ. Приложение покажет модель телевизора и активные подписки.
4. Выбрать подписку. Телефон получает её актуальные конфигурации и отправляет
   зашифрованные настройки через HTTPS API Flint.
5. ТВ сохраняет все серверы, ссылку для дальнейшего обновления, выбранную локацию,
   пользовательские сайты и автоматические правила РФ. После сохранения запускает VPN.
   **Первый системный запрос Android на создание VPN надо подтвердить пультом.**

ТВ и телефон могут находиться у разных провайдеров: например, ТВ по домашнему Wi-Fi,
телефон через мобильную сеть. Проброс портов, локальные IP и общий роутер не нужны.
Обоим нужен доступ к `https://flintmain.ru` через обычный интернет. На телефоне должен
быть новый Flint: сканировать можно из него или открыть `flint://pair` через системную камеру.

## Развёртывание отдельным модулем

Есть исходники Go без сторонних библиотек, тесты, бинарники Linux amd64/arm64 и Windows amd64.
Исходники в корне пакета; бинарники — `bin/`. При сборке самостоятельно:

```sh
go test -race ./...
CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' -o flint-pairing ./cmd/flint-pairing
./flint-pairing -listen 127.0.0.1:8099 -upstream https://flintmain.ru/api/v1 -trust-loopback-proxy
```

Установить сервис от непривилегированного пользователя, например с приложенным
`flint-pairing.service.example`. Перед сервисом нужен существующий HTTPS reverse proxy.
Добавить **один отдельный маршрут**, не заменять конфигурацию всего сайта:

```nginx
# Внутри существующего server { ... } flintmain.ru с действующим TLS.
location ^~ /api/v1/devices/pairing/ {
    proxy_pass http://127.0.0.1:8099;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header Authorization $http_authorization;
    proxy_set_header Host $host;
    proxy_read_timeout 35s;
    client_max_body_size 750k;
    # Не записывать тела запросов/ответов: в них proof и зашифрованные настройки.
}
```

`X-Real-IP` надо **перезаписывать**, не брать из внешнего заголовка. Флаг доверия
принимает его только от loopback reverse proxy. Для Docker/нескольких ingress
подключить свой механизм доверенных прокси и ограничения запросов в основном API.
Не открывать HTTP-порт сервиса наружу. CORS этому нативному клиенту не требуется.
Для проверки доступности:

```sh
curl --fail https://flintmain.ru/api/v1/devices/pairing/capabilities
# {"enabled":true,"version":1}
```

После этого проверить на тестовой подписке реальный путь **телефон на мобильной сети,
ТВ на домашней сети**. До развёртывания новый клиент сообщает, что QR без Telegram
ещё не включён на сервере, и не открывает бота вместо этой функции.

## Что модуль делает с существующим API

В обработчиках телефона `APIAuthorizer` проверяет Bearer-токен только запросами
`GET /api/v1/me` и `GET /api/v1/subscriptions` на фиксированный upstream.
Подписка должна принадлежать вошедшему аккаунту, быть активна, не истечь и не
исчерпать лимит. Идентификатор из тела запроса сам по себе права не даёт.
Модуль не выполняет login/refresh, оплату, отправку обращений и изменение сайта.

Эта версия переносит **VPN-профиль подписки**, а не полный вход в аккаунт.
Пароли, access/refresh-токены телефона и платёжные данные на ТВ не передаются.
TV-приложение не выдаёт себя за авторизованный аккаунт и не получает права владельца.
Существующая общая ссылка подписки сохраняет прежнюю модель доступа: модуль
не создаёт новый индивидуальный VPN-ключ и сам по себе не добавляет сеанс входа
в `/me/sessions`. Для отдельного отзыва ТВ/лимита устройств на backend следует
подключить штатное создание устройства со стабильным `deviceId` и выдачу
персонального ограниченного ключа; нельзя считать простой перенос общей ссылки
реализацией индивидуального отзыва устройства. Это отдельная интеграция с
вашей панелью VPN, её исходников в данном проекте нет.

## Защита и ограничения развёртывания

- QR живёт 5 минут. ID — 256 случайных бит. Подтверждение требует аккаунт телефона.
- TV держит `codeVerifier` локально; сервер хранит только SHA-256 challenge.
  QR не содержит verifier, поэтому одного QR недостаточно для получения ответа от сервера.
- Ключ AES-256-GCM находится во фрагменте QR; сервер его не получает. Конфигурация,
  включая секретную URL подписки, хранится на relay только зашифрованной.
- AAD — ASCII `Flint-TV-pairing-v1:` + pairingId. Nonce 12 байт, тег GCM 16 байт.
  Повреждённый шифротекст или данные другого QR TV отвергает.
- Только одно подтверждение. Точное повторение `requestId`+ciphertext тем же аккаунтом
  идемпотентно. Чужое или изменённое подтверждение даёт 409.
- Ответ доставляется повторно до ACK; TV сначала проверяет и сохраняет профиль,
  затем подтверждает получение. ACK удаляет шифротекст. Закрытие QR отменяет запрос.
- До 5000 ожидающих QR, до 64 MiB суммарно зашифрованных настроек, до 512 KiB
  открытого payload на одну передачу; ограничены размеры HTTP и частота запросов.
- Состояние в памяти **одного экземпляра**. Перезапуск сервиса отменяет QR.
  Для нескольких экземпляров нужен общий Redis/DB с TTL и атомарным approve/ACK,
  либо один dedicated instance за этим маршрутом. Нельзя round-robin распределять
  start/complete по независимым экземплярам. Истёкшие записи чистятся запросами.
- Ключ из QR нельзя публиковать или передавать посторонним. Не включать запись тел
  запросов/ответов и ссылок `flint://pair` в аналитику.

Тесты изолированные. Действующий API, аккаунты, оплаты и сайт при тестировании
не изменялись. Физический ТВ с мобильной сетью телефона в этой сессии не проверен.

> Нужно включить добавление Android TV по QR без Telegram и без общего Wi-Fi.

> и направьте только `/api/v1/devices/pairing/*` в этот сервис; существующий сайт
> и остальные API не заменяйте. Он проверяет наш текущий Bearer через /me и
> /subscriptions и передаёт зашифрованные настройки от телефона к ТВ.

> приложено в openapi.json. Для персонального отзыва ТВ нужна отдельная выдача
> ключа устройства вашей VPN-панелью; общая ссылка такого отзыва не обеспечивает.
