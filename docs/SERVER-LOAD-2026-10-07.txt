API нагрузки серверов — проверено 07.10.2026

GET /api/v1/locations, Authorization: Bearer <текущий токен пользователя>.
Ответ содержит items, updatedAt, loadUpdatedAt. В items: id, name, status,
addresses (массив адресов), load (целое число или null), weight (число или null).
Владелец API подтвердил: load — процент 0..100. Ноль — допустимая нагрузка.
Обновлённый Swagger прочитан через существующую сессию, сайт не изменялся.

Сопоставлять сервер по addresses и хосту профиля подписки, а не по стране/name:
два сервера в одной стране имеют разную нагрузку. Адрес с портом должен
совпадать с портом профиля. Поддерживаются имена хостов, IPv4 и IPv6.
Свежесть измерения определяется loadUpdatedAt, не updatedAt. Последнее может
обновляться при каждом запросе, даже если метрики устарели.
При возрасте >=120 секунд, времени >30 секунд в будущем, null, неверном
диапазоне или неоднозначном адресе нагрузка не используется.
status=offline со свежими данными помечает сервер недоступным.
weight не является процентом и не отображается как загрузка.

В живом API /api/v1/server-health возвращает 404; это старый контракт отдельной
интеграции. Он оставлен резервным только для API без метода /locations.
Автоматическая смена сервера остаётся только в режиме «Автоматически»;
ручной выбор не переопределяется. Действуют задержка после подключения
и подтверждение плохого состояния несколькими измерениями.
