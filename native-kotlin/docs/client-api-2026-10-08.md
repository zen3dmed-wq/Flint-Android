# Flint API для приложений — гайд разработчика

Для разработчиков клиентов Flint (Android, ПК; iOS позже). Здесь описаны сценарии и правила, без которых клиент будет работать неправильно. Полный список полей — в описании OpenAPI (см. [«Где взять OpenAPI»](#где-взять-openapi)).

**Версия API:** v1. **Состояние:** вход (email, через бота и через Telegram Login SDK), токены, профиль, привязка Telegram (через бота и SDK), устройства, подписки, покупка, продление, пробный период, рефералка, обновление приложения и поддержка. Что будет дальше — в [«Что дальше»](#что-дальше).

## Общие правила

- **Адрес:** `https://flintmain.ru/api/v1/…`, только HTTPS.
- **Формат:** JSON в camelCase. Запросы с телом — с заголовком `Content-Type: application/json`, иначе `415`.
- **Даты:** ISO-8601 в UTC с `Z`, могут быть с долями секунды: `2026-09-26T16:46:08.3618957Z`.
- **Идентификаторы** — строки, даже числовые: `"id": "-12"`, `"id": "1"`. Не приводите их к числам.
- **Перечисления** — строки в нижнем регистре: `"active"`, `"telegram"`.
- **Новые поля** сервер может добавлять в ответы без смены версии API. Неизвестные поля игнорируйте: в kotlinx.serialization — `ignoreUnknownKeys = true`, в Jackson — `FAIL_ON_UNKNOWN_PROPERTIES = false`.
- **Ответы не кэшируются:** на всех стоит `Cache-Control: no-store`.
- **Заголовок `X-Client`** — в каждом запросе, вида `платформа/версия`: `X-Client: android/1.2.0`. Сервер берёт из него версию приложения и показывает её в списке устройств.
- **Авторизация:** `Authorization: Bearer <accessToken>`.
- **Если API выключен**, сервер на любой адрес `/api/v1/…` отвечает `404` **с пустым телом**. Это не ошибка клиента: покажите «Сервис временно недоступен» и повторите позже. Обычный `404` от работающего API всегда приходит с телом ошибки (`code: not_found`).

## Ошибки

Любая ошибка приходит в формате Problem Details (`application/problem+json`):

```json
{
  "title": "Bad Request",
  "status": 400,
  "code": "validation_failed",
  "detail": "Проверьте введённые данные.",
  "errors": {
    "email": ["Некорректный email."],
    "device.platform": ["Платформа должна быть одной из: android, windows, macos, linux, ios."]
  },
  "traceId": "0HNORTV87DT19"
}
```

- **`code`** — машинный код. Ветвитесь только по нему, `title` и `status` — справочно.
- **`detail`** — текст на русском, его можно показать пользователю. Может отсутствовать.
- **`errors`** — только у `validation_failed`: ошибки по полям, ключи в camelCase через точку (`device.platform`).
- **`traceId`** — пишите в лог и в обращения в поддержку: по нему находится запрос на сервере.

Все коды и что с ними делать — в [шпаргалке](#шпаргалка-ответ--действие).

## Лимиты частоты

| Что | Лимит | Ключ |
|---|---|---|
| Любые запросы вошедшего пользователя | 120 в минуту | пользователь |
| Любые запросы без входа | 300 в минуту | IP |
| Вход (email или Telegram SDK), регистрация, старт входа или привязки через бота, привязка через Telegram SDK, добавление входа по email, смена пароля, ввод реферального кода | 30 за 10 минут | IP |
| Создание заказа, продления и пробного периода, новая ссылка на оплату, перевыпуск ссылки подписки | 10 за 10 минут | пользователь |
| Новое обращение в поддержку | 5 в час | пользователь |
| Сообщение в поддержку | 30 за 10 минут | пользователь |
| Успешные регистрации | 3 в час | IP |

При превышении — `429 rate_limited`. Если есть заголовок `Retry-After` (секунды), не повторяйте раньше.

## Объект device

Передаётся при входе и регистрации: по нему сессия привязывается к устройству.

```json
{
  "deviceId": "7f9c2b1e-4d8a-4f3e-9b6a-2c1d0e5f7a8b",
  "platform": "android",
  "model": "Pixel 8",
  "osVersion": "14",
  "appVersion": "1.2.0"
}
```

| Поле | Обязательно | Ограничения |
|---|---|---|
| `deviceId` | да | до 64 символов |
| `platform` | да | `android`, `windows`, `macos`, `linux`, `ios` |
| `model` | нет | до 100 символов |
| `osVersion` | нет | до 50 символов |
| `appVersion` | нет | до 50 символов |

- **`deviceId`** — случайный UUID. Сгенерируйте его при первом запуске и храните до удаления приложения. Аппаратные идентификаторы не используйте.
- **Одна сессия на устройство:** повторный вход того же пользователя с того же `deviceId` закрывает его прежнюю сессию на этом устройстве.
- `model`, версии и IP пользователь видит в списке устройств, а при входе через бота — ещё и в сообщении бота.

## Токены и сессии

Любой вход (email, бот или Telegram SDK) возвращает пару токенов:

```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9…",
  "accessTokenExpiresAt": "2026-09-26T12:15:00Z",
  "refreshToken": "3f0c9a…e41b.Qm9vT2x…",
  "refreshTokenExpiresAt": "2026-12-25T12:00:00Z"
}
```

- **Access-токен** — JWT на 15 минут. Храните в памяти. Не разбирайте его содержимое: данные пользователя берите из `GET /me`.
- **Refresh-токен** — непрозрачная строка. Сессия живёт 90 дней и продлевается при каждом обновлении. Храните его в защищённом хранилище: на Android — Keystore (EncryptedSharedPreferences или DataStore с шифрованием), на Windows — DPAPI или Credential Manager, на macOS — Keychain, на Linux — libsecret.

### Обновление токенов

`POST /auth/refresh {refreshToken}` → новая пара. **Прежний refresh-токен после этого недействителен:** сразу сохраните новый.

**Обновляйте строго по одному (single-flight).** Если несколько запросов одновременно получили `401`, обновление делает один из них, остальные ждут его результата и повторяются с новым access-токеном. Два параллельных refresh с одним токеном могут закончиться отзывом всей сессии: сервер считает повторно предъявленный старый токен украденным.

```kotlin
private val refreshMutex = Mutex()

// staleToken — access-токен, с которым запрос получил 401.
suspend fun accessTokenAfter401(staleToken: String): String? = refreshMutex.withLock {
    tokens.accessToken?.takeIf { it != staleToken }?.let { return it } // уже обновил другой запрос
    val refresh = tokens.refreshToken ?: return null
    when (val result = api.refresh(refresh)) {
        is Ok -> tokens.save(result.pair).accessToken
        else -> null // разбор кодов — ниже
    }
}
```

**Когда обновлять:** на `401 unauthorized` — один refresh и один повтор запроса. Можно и заранее, за минуту до `accessTokenExpiresAt`, но часы устройства могут расходиться с серверными, поэтому обработка `401` нужна в любом случае.

**Ответ refresh не дошёл** (обрыв сети): повторите с **тем же** токеном в течение минуты — сервер примет его ещё раз. Позже старый токен считается повторным, сессия закроется, и пользователю придётся войти заново.

**Ответы refresh:**

| Ответ | Что делать |
|---|---|
| `200` | сохранить новую пару |
| `401 invalid_refresh_token` | сессии больше нет (выход, отзыв с другого устройства или поддержкой, смена или сброс пароля, блокировка, истекла) — стереть токены, экран входа |
| `403 account_banned` | экран блокировки; токены не стирать. Блокировка закрывает сессии: после разблокировки refresh ответит `401 invalid_refresh_token` — войти заново |
| `503 maintenance` | экран техработ; refresh-токен не менялся, повторить позже |
| сеть или `5xx` | повторить позже с тем же токеном (см. выше про одну минуту) |

### Выход

`POST /auth/logout {refreshToken}` → всегда `204`, даже для недействительного токена. После этого сотрите токены у себя. Access-токен закрытой сессии перестаёт работать сразу, а не через 15 минут.

## Вход по email

Email не подтверждается, писем сервер не шлёт. Пароль — от 8 до 128 символов, других требований нет.

**Регистрация:** `POST /auth/register`

```json
{ "email": "user@mail.ru", "password": "…", "referralCode": "AB12CD34", "device": { … } }
```

- `referralCode` необязателен, регистр неважен. Неизвестный код — `400 invalid_referral_code`. Указать код можно и позже, см. [«Рефералка»](#рефералка--referrals).
- `200` — пара токенов, пользователь сразу вошёл.
- `403 registration_closed` — регистрация по email выключена на сервере: предложите вход через Telegram. Заранее это видно в `/config` (`auth.emailRegistration`).
- `409 email_taken` — такой email уже есть: предложите войти.
- `429 rate_limited` — с этого IP недавно уже регистрировались.

**Вход:** `POST /auth/login {email, password, device}` → пара токенов. Email — в любом регистре.

- `401 invalid_credentials` — неверный email или пароль (сервер не говорит, что именно).
- `429 account_locked` — пять неверных паролей подряд, вход закрыт на 15 минут. Сколько осталось — в `detail`. Пока вход закрыт, отказ будет и с верным паролем.

**Забыли пароль:** сбросить его можно только через поддержку — администратор выдаст новый. Покажите ссылку на поддержку из `/config` (`links.support`). После сброса все устройства пользователя разлогинены.

## Вход через Telegram-бота

Работает одинаково на Android и ПК. Приложение получает ссылку на бота, пользователь подтверждает вход кнопкой в боте, а приложение тем временем опрашивает сервер.

**1. Сгенерируйте PKCE-пару** (RFC 7636, метод S256): `codeVerifier` — 32 случайных байта в base64url без `=`, `codeChallenge` — base64url(SHA-256(codeVerifier)).

```kotlin
val encoder = Base64.getUrlEncoder().withoutPadding()
val verifier = encoder.encodeToString(ByteArray(32).also { SecureRandom().nextBytes(it) })
val challenge = encoder.encodeToString(
    MessageDigest.getInstance("SHA-256").digest(verifier.toByteArray(Charsets.US_ASCII)))
```

```csharp
static string Base64Url(byte[] bytes) =>
    Convert.ToBase64String(bytes).TrimEnd('=').Replace('+', '-').Replace('/', '_');

var verifier = Base64Url(RandomNumberGenerator.GetBytes(32));
var challenge = Base64Url(SHA256.HashData(Encoding.ASCII.GetBytes(verifier)));
```

`java.util.Base64` есть с Android 8.0 (API 26); на более старых — `android.util.Base64` с флагами `URL_SAFE or NO_PADDING or NO_WRAP`.

`codeVerifier` не покидает устройство до шага 3. Поэтому подсмотренная ссылка на бота бесполезна: токены получит только приложение, которое начало вход.

**2. Старт:** `POST /auth/telegram/bot/start {codeChallenge, device}`

```json
{
  "loginId": "9f2c4e7a1b3d5f60718293a4b5c6d7e8",
  "botUrl": "https://t.me/Flintgo_bot?start=login_9f2c4e7a1b3d5f60718293a4b5c6d7e8",
  "expiresAt": "2026-09-26T12:05:00Z"
}
```

- Откройте `botUrl` как есть, сами ссылку не собирайте. На Android — `Intent.ACTION_VIEW`: откроется Telegram или браузер. На ПК — браузер, и рядом покажите QR-код с `botUrl`, чтобы подтвердить вход с телефона.
- Запрос живёт 5 минут (`expiresAt`).
- Бот покажет устройство, версию приложения, IP и время, и кнопки «✅ Подтвердить» / «❌ Это не я». Подтвердить может только тот аккаунт Telegram, который первым открыл ссылку.

**3. Опрос:** `POST /auth/telegram/bot/complete {loginId, codeVerifier}` — раз в 2 секунды, пока не придёт окончательный ответ или не наступит `expiresAt`.

| Ответ | Значит | Что делать |
|---|---|---|
| `202 {"status": "pending", "expiresAt": …}` | ещё не подтверждено | продолжать опрос |
| `200` | пара токенов и `isNewAccount` | вход выполнен, опрос остановить |
| `410 login_expired` | срок вышел, запроса нет или он уже использован | остановить, предложить начать заново |
| `410 login_rejected` | нажато «Это не я» | остановить, сообщить пользователю |
| `400 invalid_code_verifier` | verifier не от этого старта | ошибка в клиенте; начать заново |
| `403 account_banned`, `503 maintenance` | см. [«Техработы и блокировка»](#техработы-и-блокировка) | |

- Токены выдаются один раз. Повторный `complete` после `200` вернёт `410`.
- **`isNewAccount: true`** — этого пользователя бота создал сам этот вход. Если у человека уже есть аккаунт с email, это разные аккаунты, и подписки там не видны. Предложите выйти, войти по email и [привязать Telegram](#привязать-telegram): пустой аккаунт бота объединится с аккаунтом по email.

## Вход через Telegram Login SDK (Android)

Вход через официальный SDK Telegram ([telegram-login-android](https://github.com/TelegramMessenger/telegram-login-android)). Приложение Telegram на телефоне само спрашивает подтверждение и возвращает приложению `idToken` — JWT, подписанный Telegram. Бот в этом входе не участвует. Кнопку показывайте, только если в `/config` пришло `auth.telegramOidc: true`; иначе остаётся [вход через бота](#вход-через-telegram-бота). На ПК — вход через бота.

**Настройка SDK.** `clientId` выдаёт владелец сервиса: он регистрирует приложение в BotFather (Login Widget — имя пакета и SHA-256 ключа подписи). Адрес возврата — как в README SDK. Scopes:
- `profile` — **обязательно**: без него в токене нет id пользователя, и сервер ответит `401 invalid_id_token`;
- `telegram:bot_access` — рекомендуем: с ним бот сможет писать пользователю (ссылка на подписку, напоминания, уведомления о входе). Человеку, который ни разу не писал боту, без этого разрешения сообщения бота не придут. Всё нужное приложение и так показывает через API;
- `phone` не запрашивайте: сервер номер не использует.

**Вход:** `POST /auth/telegram/oidc`

```json
{ "idToken": "eyJhbGciOiJSUzI1NiIsImtpZCI6Im9pZGMtMSJ9…", "device": { … } }
```

| Ответ | Значит | Что делать |
|---|---|---|
| `200` | пара токенов и `isNewAccount`, как у входа через бота | вход выполнен |
| `401 invalid_id_token` | токен не принят: выпущен для другого `clientId`, истёк, уже использован, в нём нет id (scope `profile`) или он не от Telegram. Причина — в `detail` | запустить вход через SDK заново; тот же токен не повторять |
| `503 telegram_oidc_unavailable` | вход через SDK выключен на сервере или сервер не получил ключи Telegram | предложить вход через бота, повторить позже |
| `403 account_banned`, `503 maintenance` | см. [«Техработы и блокировка»](#техработы-и-блокировка) | |

- **Каждый `idToken` принимается один раз** и живёт час. Отправляйте его сразу после входа в SDK. Если ответ не дошёл, повтор с тем же токеном получит `401`: начните вход заново.
- **Аккаунт тот же, что при входе через бота:** у пользователя Telegram один аккаунт, каким бы способом он ни входил. Имя и username обновляются из токена.
- **`isNewAccount: true`** — этот вход впервые завёл пользователя Telegram. Как и при входе через бота: если у человека уже есть аккаунт с email, предложите войти по email и [привязать Telegram](#привязать-telegram).
- В списке устройств такая сессия — `authMethod: "telegram"`.
- Лимит — как у входа. Тот же эндпоинт подойдёт iOS-клиенту с `telegram-login-ios`.

## Запуск приложения

1. `GET /config` — способы входа, ссылки, техработы. Нужен и до входа.
2. Нет сохранённого refresh-токена — экран входа. Показывайте только способы из `config.auth`.
3. Есть — `POST /auth/refresh`, дальше по таблице ответов refresh.
4. После успешного refresh — `GET /config` ещё раз, уже с access-токеном: для пользователей из списка исключений техработы в нём показаны выключенными. Затем `GET /me` и `GET /subscriptions`.

## Техработы и блокировка

**Техработы.** Пока они идут, API отвечает `503 maintenance` почти на всё. Работают только `/config`, выход, старт входа через бота, [проверка обновления и скачивание его файла](#обновление-приложения--appupdate). Пользователей, которых администратор пустил во время работ, сервер узнаёт при входе и refresh и обслуживает как обычно. В `detail` — текст для пользователя, его задаёт администратор.

- `/config` → `maintenance: {enabled, message}` — подсказка на старте. С access-токеном ответ учитывает пользователя: тем, кого администратор пустил во время работ, придёт `enabled: false`.
- Окончательный сигнал — `503 maintenance` на любом запросе. Покажите экран с `detail` и кнопкой «Повторить».
- Вход через бота во время работ проходит только у пользователей из списка исключений. Остальным бот не покажет подтверждение, и вход истечёт (`410`). Поэтому перед стартом входа проверьте `config.maintenance`.

**Блокировка.** `403 account_banned` на любом запросе, при входе и при refresh. Покажите экран «Аккаунт заблокирован» со ссылкой на поддержку и не повторяйте запросы.

Блокировка закрывает все сессии пользователя, а его активные подписки истекают. Пока бан в силе, старые токены получают `403 account_banned`. После разблокировки они не вернутся: refresh ответит `401 invalid_refresh_token`, нужно войти заново.

## Конфигурация — GET /config

Без авторизации, работает и в техработы. Access-токен необязателен (см. выше про техработы).

```json
{
  "maintenance": { "enabled": false, "message": null },
  "auth": { "emailLogin": true, "emailRegistration": false, "telegramBot": true, "telegramOidc": false },
  "purchasesEnabled": false,
  "referralsEnabled": true,
  "trial": { "mode": "everyone", "days": 3 },
  "bot": { "username": "Flintgo_bot", "url": "https://t.me/Flintgo_bot" },
  "links": {
    "support": "https://t.me/…",
    "news": "https://t.me/…",
    "chat": "https://t.me/…",
    "userAgreement": "https://…",
    "privacyPolicy": "https://…",
    "instructions": { "android": "https://…", "ios": "https://…", "windows": "https://…", "macos": null }
  }
}
```

| Поле | Как использовать |
|---|---|
| `auth.emailRegistration` | `false` — спрятать регистрацию по email (вход по email остаётся) |
| `auth.telegramBot` | `false` — спрятать вход через бота |
| `auth.telegramOidc` | `true` — показать на Android [вход через Telegram Login SDK](#вход-через-telegram-login-sdk-android) |
| `purchasesEnabled` | `false` — спрятать покупку и продление: [каталог](#покупка-тарифы-и-способы-оплаты) отвечает `503 purchases_disabled` |
| `referralsEnabled` | начисляются ли бонусы за друзей; `false` — спрятать [рефералку](#рефералка--referrals) |
| `trial` | [пробный период](#пробный-период--subscriptionstrial): `mode` — кому он доступен (`everyone` — всем, `telegram_only` — только аккаунтам с Telegram), `days` — его срок. Доступен ли он этому пользователю — `trialAvailable` в `/me` |
| `bot` | бот для кнопки «Открыть бота»; `null`, если не настроен |
| `links.*` | ссылки для экранов «Поддержка», «О приложении», «Как подключиться». Любая может быть `null` — тогда пункт не показывать |

Запрашивайте при запуске и при возврате в приложение: флаги меняются на сервере без выпуска новой версии.

## Профиль — /me

`GET /me`:

```json
{
  "id": "777",
  "email": null,
  "hasPassword": false,
  "telegram": { "id": "777", "username": "ivan", "firstName": "Иван", "lastName": null },
  "referralCode": "IXP06QB6",
  "hasReceivedTrial": true,
  "trialAvailable": false
}
```

- `telegram` — `null` у аккаунта без Telegram (зарегистрирован по email). Telegram можно [привязать](#привязать-telegram).
- `id` меняется один раз — при привязке Telegram.
- `hasPassword: false` — показывайте «Добавить вход по email», `true` — «Сменить пароль».
- `hasReceivedTrial` — получал ли пользователь пробный период.
- `trialAvailable` — можно ли получить [пробный период](#пробный-период--subscriptionstrial): ещё не получал, и режим сервера это разрешает. Кнопку пробного периода показывайте только при `true`.

### Добавить вход по email

`POST /me/email-login {email, password}` → `200` и обновлённый профиль. Так пользователь, вошедший через Telegram, сможет входить по email, например на ПК без Telegram. Это тот же аккаунт с теми же подписками.

- `409 email_login_exists` — вход по email уже есть. Он есть всегда, если аккаунт регистрировали по email.
- `409 email_taken` — этот email принадлежит другому аккаунту. Предложите войти по нему и [привязать Telegram](#привязать-telegram) там.
- Бот пришлёт пользователю в Telegram уведомление о новом способе входа.

### Сменить пароль

`PUT /me/password {currentPassword, newPassword}` → `204`.

- Все устройства, кроме текущего, разлогиниваются. Текущее продолжает работать с прежними токенами.
- `400 invalid_current_password` — неверный текущий пароль. Это не проблема с токенами, обновлять их не нужно. Неверные попытки считаются вместе со входом: после пяти подряд — `429 account_locked`.
- `400 validation_failed` — новый пароль короче 8 символов или совпадает с текущим.
- `409 password_not_set` — входа по email нет, сначала добавьте его.

### Привязать Telegram

Аккаунт, зарегистрированный по email (`telegram: null`), можно привязать к Telegram. После этого в него можно входить и через бота, а подписки из бота и из приложения окажутся в одном аккаунте. Механизм — как у [входа через бота](#вход-через-telegram-бота), только без PKCE: запрос принадлежит сессии, которая его начала.

1. `POST /me/telegram/bot/start` без тела → `{loginId, botUrl, expiresAt}`, как у входа. Откройте `botUrl`, на ПК покажите и QR-код. Запрос живёт 5 минут.
2. Бот покажет email аккаунта, устройство, IP и время и кнопки «✅ Подтвердить» / «❌ Это не я». Подтвердить может только тот аккаунт Telegram, который первым открыл ссылку. Данные переносятся в момент нажатия — даже если приложение к этому времени закрыто.
3. Опрашивайте `POST /me/telegram/bot/complete {loginId}` раз в 2 секунды:

| Ответ | Значит | Что делать |
|---|---|---|
| `202 {"status": "pending", "expiresAt": …}` | ещё не подтверждено | продолжать опрос |
| `401 unauthorized` | Telegram привязан, id аккаунта сменился | обычный refresh и повтор, см. ниже |
| `200` | профиль, как в `GET /me`, уже с `telegram` | готово: обновить `/subscriptions` и `/referrals` |
| `409 already_linked` | у этого Telegram уже есть свой аккаунт | остановить; предложить войти через Telegram или написать в поддержку |
| `410 login_rejected` | нажато «Это не я» | остановить |
| `410 login_expired` | срок вышел, привязать не удалось или запрос начат на другом устройстве | предложить начать заново |

**id аккаунта меняется.** Аккаунт переезжает на Telegram id: `id` в `/me` станет равен `telegram.id`. Access-токены всех устройств этого аккаунта сразу перестают действовать — ближайший запрос получит `401 unauthorized`. Обычный refresh тем же refresh-токеном выдаст новую пару, входить заново не нужно. Если приложение хранит id пользователя, возьмите новый из `/me`.

**Что куда переезжает.** Историей считаются подписки, оплаты и приглашённые друзья; неоплаченные заказы не в счёт. Если история есть только у одной стороны, аккаунты объединятся сами:
- у Telegram истории нет — к нему переезжает всё: подписки, заказы, рефералка (код, пригласивший, друзья), вход по email и устройства;
- истории нет у аккаунта по email — к пользователю бота переезжают вход по email и устройства, код и подписки остаются из бота.

Ссылки подписок не меняются. По перенесённым подпискам бот теперь присылает обычные сообщения: напоминания об окончании, продления.

**`409 already_linked`** — история есть у обоих или у этого Telegram уже есть свой вход по email. Такие аккаунты автоматически не объединяются: предложите войти через Telegram или написать в поддержку.

- `409 telegram_already_linked` на старте — к аккаунту уже привязан Telegram (`telegram` в `/me` не `null`). Таким аккаунтам кнопку привязки не показывайте.
- Лимит старта — как у входа.
- Если приложение перезапустилось посреди привязки, итог виден в `/me` после refresh.
- После `200` покажите, какой Telegram привязан (`telegram.username` или имя). Ссылку, как и при входе, может первым открыть и чужой Telegram — например, сфотографировав QR-код с экрана. Если аккаунт не его, пусть напишет в поддержку.

### Привязать через Telegram Login SDK (Android)

Если в `/config` пришло `auth.telegramOidc: true`, на Android Telegram можно привязать без бота. [Вход в SDK](#вход-через-telegram-login-sdk-android) выдаёт `idToken`, его отправляют в `POST /me/telegram/oidc`:

```json
{ "idToken": "eyJhbGciOiJSUzI1NiIsImtpZCI6Im9pZGMtMSJ9…" }
```

Правила переноса, смена id аккаунта и `409 already_linked` — те же, что при привязке через бота.

| Ответ | Значит | Что делать |
|---|---|---|
| `200` | профиль, как в `GET /me`, уже с `telegram` | готово. Следующий запрос получит `401 unauthorized`: обычный refresh, затем `/subscriptions` и `/referrals` |
| `400 invalid_id_token` | токен не принят, причина в `detail`. Сессия в порядке, токены не обновлять | запустить вход в SDK заново |
| `409 already_linked` | у этого Telegram уже есть свой аккаунт или его нельзя привязать | предложить войти через Telegram или написать в поддержку |
| `409 telegram_already_linked` | к аккаунту уже привязан Telegram | обновить `/me` |
| `503 telegram_oidc_unavailable` | привязка через SDK выключена или ключи Telegram недоступны | предложить привязку через бота |

- Данные переносятся сразу, в этом же запросе. Если ответ не дошёл, обновите токены и посмотрите `/me`: повтор с тем же `idToken` получит `400`.
- Бот напишет в Telegram, что к нему привязан аккаунт с этим email, если может писать пользователю (разрешение `telegram:bot_access` или переписка с ботом раньше).
- Лимит — как у входа.

## Подписки — /subscriptions

`GET /subscriptions` — активные и истёкшие подписки: сначала активные (с поздним окончанием выше), потом истёкшие. `GET /subscriptions/{id}` — одна подписка в том же виде.

```json
{
  "items": [
    {
      "id": "2eb94200-feef-41bf-96dd-d384d7965f5d",
      "status": "active",
      "plan": { "id": "1", "name": "1 месяц" },
      "startedAt": "2026-09-26T16:46:08Z",
      "expiresAt": "2026-10-26T16:46:08Z",
      "subscriptionUrl": "https://…/sub/…",
      "traffic": {
        "usedBytes": 5368709120,
        "limitBytes": 1073741824000,
        "updatedAt": "2026-09-26T14:46:08Z",
        "limitReached": false
      }
    },
    {
      "id": "03b0ef13-643d-4c0a-ae95-dde026ca20a1",
      "status": "expired",
      "plan": { "id": "1", "name": "1 месяц" },
      "startedAt": "2026-08-01T10:00:00Z",
      "expiresAt": "2026-09-01T10:00:00Z",
      "subscriptionUrl": null,
      "traffic": null
    }
  ]
}
```

- **`status`** — `active` или `expired`. Неоплаченных записей в списке нет: это заказы, они появятся в этапе 2. Записи, которые пользователь удалил в боте, скрыты.
- **`subscriptionUrl`** — ссылка подписки Marzban, та же, что показывает бот. Импортируйте её в VPN-ядро как подписку. У старых записей вместо неё бывает `vless://…` — импортируйте как одиночную конфигурацию. У истёкшей подписки ссылки нет: пользователь на VPN-сервере уже удалён. Если истёкшую подписку продлила поздняя оплата, ссылка у неё новая. Ссылка меняется и после [перевыпуска](#перевыпустить-ссылку).
- **Конфигурации в подписке** задаёт сервер, и у разных подписок они могут отличаться: VLESS с flow `xtls-rprx-vision` или без него, а также другие протоколы Marzban — VMess, Trojan, Shadowsocks. VPN-ядро должно принимать подписку с несколькими протоколами. Если набор у пользователя поменяется, ссылка остаётся прежней: новые конфигурации приходят при обновлении подписки, а после смены flow старые перестают работать, пока подписка не обновится. Оплаченное продление набор только дополняет: добавляет конфигурации, но ничего не убирает и flow не меняет. Поэтому обновляйте подписку в VPN-ядре при запуске приложения и после оплаты продления.
- **`plan.name`** — название тарифа. Срок подписки может отличаться от срока тарифа (продления, бонусы), поэтому ориентируйтесь на `expiresAt`.
- **`traffic`** — только у активной подписки:
  - `limitBytes` — лимит этой подписки в месяц. У разных подписок он может быть разным: его задаёт тариф при покупке, а оплаченное продление ставит лимит тарифа, но не ниже прежнего;
  - `limitBytes: null` — безлимит;
  - `updatedAt: null` — снимка ещё не было, показывайте «нет данных», а не 0. Снимок обновляется периодически, показывайте его возраст («обновлено 2 ч назад»);
  - `limitReached: true` — лимит исчерпан. Расход обнуляется раз в месяц. Продление вернёт доступ по трафику, только если новый лимит выше израсходованного. Текст как в боте: «Лимит трафика исчерпан. Расход обнуляется раз в месяц.»
- Чужая или скрытая подписка — `404`. Данные берутся из базы, поэтому частый опрос не нужен: обновляйте при открытии экрана и по жесту «потянуть вниз».
- Активную подписку можно [продлить](#продление--subscriptionsidrenewals).

### Перевыпустить ссылку

Если ссылка подписки утекла, пользователь сам получает новую: `POST /subscriptions/{id}/reissue-link` без тела. Ответ — `200` и подписка в том же виде, что в `GET /subscriptions/{id}`, уже с новой `subscriptionUrl`.

- **Старая ссылка и все VPN-клиенты, настроенные по ней, сразу перестают работать** — на всех устройствах, в том числе в сторонних приложениях: VPN-сервер меняет и ссылку, и ключи. Перед запросом спросите подтверждение, после — замените подписку в VPN-ядре новой ссылкой.
- Перевыпустить можно только активную подписку: истёкшая — `409 subscription_not_active`, чужая или скрытая — `404`.
- `502 panel_failed` — VPN-сервер не ответил, повторите позже. Перечитайте подписку и, если ссылка в ней изменилась, замените её в VPN-ядре: сервер мог успеть сменить ссылку, не ответив.
- Повторное нажатие, пока первый запрос не закончился, второй раз ссылку не меняет: оба ответа придут с одной и той же новой ссылкой.
- Пользователь с Telegram получит в боте сообщение с новой ссылкой, и «Мои подписки» в боте покажут её же.
- Лимит — общий с заказами.

### История трафика

`GET /subscriptions/{id}/traffic` — сколько трафика подписка тратила по дням:

```json
{
  "from": "2026-08-29",
  "to": "2026-09-27",
  "items": [
    { "date": "2026-09-26", "usedBytes": 1288490188 },
    { "date": "2026-09-27", "usedBytes": 536870912 }
  ],
  "updatedAt": "2026-09-27T09:00:00Z"
}
```

- **Дни — по Москве:** `date`, `from` и `to` — даты `yyyy-MM-dd` без времени. `to` — сегодня, этот день ещё идёт.
- **Окно** — последние 30 дней, включая сегодня. Другое окно — `?days=N`, от 1 до 90: `?days=7` — неделя. Иначе `400 validation_failed`.
- **В `items` только дни с расходом**, по порядку. Остальные дни окна рисуйте нулём.
- **Расход считает синхронизация с VPN-сервером**, раз в несколько часов. `updatedAt` — время последней: что потрачено после неё, появится со следующей (`null` — синхронизации ещё не было). Расход между синхронизациями делится между днями пропорционально времени, так что граница дней примерная: часть вечернего расхода может попасть на следующий день.
- **История копится с того дня, когда её включили на сервере.** Дни до этого придут без расхода.
- **Остаток лимита** считайте по `traffic` из подписки, а не по сумме истории: история знает только то, что застала синхронизация.
- У истёкшей подписки — история до окончания. Чужая или скрытая подписка — `404`, как в `GET /subscriptions/{id}`.
- Данные меняются только после синхронизации: обновляйте при открытии экрана.

## Локации — /locations

`GET /locations` — локации VPN: статус, адреса и загрузка.

```json
{
  "items": [
    { "id": "1", "name": "🇩🇪 Германия", "status": "online", "addresses": ["203.0.113.10"], "load": 30, "weight": 44 },
    { "id": "2", "name": "🇳🇱 Нидерланды", "status": "online", "addresses": ["198.51.100.7"], "load": 10, "weight": 56 },
    { "id": "3", "name": "🇫🇮 Финляндия", "status": "offline", "addresses": ["192.0.2.25"], "load": null, "weight": null }
  ],
  "updatedAt": "2026-10-04T12:00:00Z",
  "loadUpdatedAt": "2026-10-04T12:00:41Z"
}
```

- **Подписка одна на все локации:** конфигурации всех локаций приходят в одной подписке, а приложение выбирает, к какой подключиться.
- `id` — постоянный ключ элемента списка, строкой.
- `name` — название, как его задал администратор на VPN-сервере. В подписке конфигурации могут называться иначе, поэтому сопоставляйте их по адресу, а не по названию.
- `status`: `online` — локация на связи с сервером, `offline` — нет. Это не пинг и не скорость: их меряйте в VPN-ядре. Локаций, выключенных администратором, в списке нет.
- `addresses` — адреса серверов локации. Конфигурация из подписки относится к локации, если адрес её сервера совпадает с одним из `addresses` без учёта регистра. Это `host` в `vless://uuid@host:port?…` (так же у `trojan://`, `ss://`) или `server` в JSON-конфигурации ядра. У одной локации бывает несколько конфигураций, по одной на протокол. Пустой массив — адреса нет, и конфигурации этой локации не узнать.
- `load` — загрузка канала локации, от 0 до 100: средний поток за последние 15 минут против её пропускной способности. 100 — канал забит. `null` — данных нет: локация `offline`, сбор только начался или данные устарели. Пользователю её удобно показывать полосой.
- `weight` — вес для автовыбора: доля свободной пропускной способности локации среди локаций `online`. Веса есть у всех локаций `online` сразу или ни у одной; у `offline` — всегда `null`. Сумма — около 100, но веса относительные.
- `loadUpdatedAt` — когда мерили загрузку. `null` — свежих данных нет, и `load` и `weight` у всех `null`.
- `updatedAt` — когда сервер получил статусы. Статусы и загрузка обновляются раз в минуту, чаще опрашивать не нужно. Если VPN-сервер не ответил, приходит прошлый список, и `updatedAt` показывает, насколько он старый.
- `503 locations_unavailable` — свежих статусов нет больше 15 минут: покажите «нет данных» или спрячьте экран.

### Как выбирать локацию автоматически

1. Сопоставьте конфигурации подписки с локациями по `addresses`. Сначала выбирается локация, потом её конфигурация — протокол.
2. Кандидаты — только локации `online`.
3. Проверьте доступность и пинг каждой локации с устройства, через VPN-ядро. Это обязательно: сервер не видит блокировок у провайдера пользователя, а заблокированная у него локация выглядит пустой, и вес у неё самый большой.
4. Оставьте локации с пингом не хуже лучшего плюс ваш порог, например 50–100 мс.
5. Выберите из них одну случайно, с вероятностью, пропорциональной `weight`: переведите веса оставшихся локаций в доли. Не берите всегда локацию с самым большим весом или самой малой загрузкой — тогда все приложения разом уйдут на одну и перегрузят её.
6. Если `weight` у всех `null`, выбирайте по пингу. Конфигурации, которые не совпали ни с одной локацией, загрузки не имеют: берите их, только если не подошла ни одна локация с весом.
7. Выбирайте при подключении. Активное подключение из-за загрузки не переключайте — только при обрыве или если локация стала `offline`.

## Покупка: тарифы и способы оплаты

Каталог работает, только когда на сервере включены покупки: `purchasesEnabled` в `/config`. Иначе оба эндпоинта отвечают `503 purchases_disabled` — спрячьте покупку и не повторяйте запрос, пока `/config` не покажет `purchasesEnabled: true`.

`GET /plans` — тарифы, которые этот пользователь может купить, в том же порядке, что в боте:

```json
{
  "items": [
    {
      "id": "5",
      "name": "1 месяц",
      "durationDays": 30,
      "price": { "amount": "200.00", "currency": "RUB" },
      "savings": null,
      "savingsPercent": null,
      "availableUntil": null,
      "isPersonal": false,
      "traffic": { "limitBytes": 1073741824000 }
    },
    {
      "id": "7",
      "name": "3 месяца",
      "durationDays": 90,
      "price": { "amount": "500.00", "currency": "RUB" },
      "savings": { "amount": "100.00", "currency": "RUB" },
      "savingsPercent": 17,
      "availableUntil": null,
      "isPersonal": false,
      "traffic": { "limitBytes": 1073741824000 }
    },
    {
      "id": "12",
      "name": "Неделя за 50 ₽",
      "durationDays": 7,
      "price": { "amount": "50.00", "currency": "RUB" },
      "savings": null,
      "savingsPercent": null,
      "availableUntil": "2026-10-01T21:00:00Z",
      "isPersonal": false,
      "traffic": { "limitBytes": 107374182400 }
    }
  ]
}
```

- **Деньги** — объект `{amount, currency}`, `amount` — строка с двумя знаками после точки. Не переводите её во float: показывайте как есть или считайте в decimal.
- **`savings`, `savingsPercent`** — выгода против покупки по месяцу, те же цифры, что на кнопке в боте. `null` — выгоды нет, бейдж не показывайте.
- **`availableUntil`** — акция, тариф пропадёт в это время. `null` — без срока.
- **`isPersonal`** — персональное предложение: тариф выдан только этому пользователю.
- **`traffic.limitBytes`** — лимит трафика в месяц, с которым выдаётся подписка этого тарифа; `null` — безлимит. У тарифов он бывает разным, поэтому показывайте его рядом с ценой.
- `durationDays` — сколько дней добавит покупка.
- Список меняется без выпуска приложения: акции начинаются и заканчиваются, тарифы включают и выключают. Запрашивайте его при открытии экрана покупки. Пустой `items` — купить сейчас нечего.

`GET /payment-methods` — доступные способы оплаты, в том же порядке, что в боте:

```json
{
  "items": [
    { "id": "platega", "title": "Карта, СБП, крипта" },
    { "id": "cryptobot", "title": "Криптовалюта (USDT)" }
  ]
}
```

- `id` приложение передаст при [создании заказа](#заказы--orders). `title` показывайте как есть, тогда новый способ оплаты появится без выпуска приложения.
- `platega` — одна форма, на которой человек сам выбирает карту, СБП, SberPay или криптовалюту.
- `cryptobot` — оплата в USDT через Crypto Bot. Рублёвая цена пересчитывается по курсу, сумму в USDT сервер вернёт вместе с заказом. Приложению отдаётся ссылка на веб-версию Crypto Bot: она открывается в браузере, а не в Telegram.
- Любой способ может пропасть: администратор выключил его или не задал курс. Пустой список — оплатить сейчас нечем.

## Заказы — /orders

Покупка — это заказ. Приложение создаёт его, открывает ссылку на оплату и опрашивает статус, пока заказ не станет оплаченным.

**Создать:** `POST /orders`. Заголовок `Idempotency-Key` необязателен, но без него нельзя безопасно повторить запрос (см. ниже):

```json
{ "planId": "7", "provider": "platega" }
```

Ответ — `201 Created` с заголовком `Location: /api/v1/orders/{id}`:

```json
{
  "id": "44994fe5-3079-4e9f-be27-58825ee3ae57",
  "type": "purchase",
  "status": "pending",
  "plan": { "id": "7", "name": "3 месяца" },
  "days": 90,
  "provider": "platega",
  "subscriptionId": null,
  "payment": {
    "url": "https://pay.platega.io/…",
    "amount": { "amount": "500.00", "currency": "RUB" },
    "displayAmount": null
  }
}
```

- `planId` берите из `/plans`, `provider` — из `/payment-methods`.
- `type` — `purchase` у покупки и `renewal` у [продления](#продление--subscriptionsidrenewals).
- `days` — на сколько дней заказ выдаст или продлит подписку. `null` бывает только у старых оплаченных продлений: их срок не сохранился, не показывайте его.
- `payment.url` — ссылка на оплату (как её открыть — ниже, в «После оплаты»). `payment.amount` — цена. `displayAmount` — сумма в валюте оплаты, если она другая: у крипты «6.25 USDT». Показывайте обе.
- **`Idempotency-Key`** — новый UUID на каждое нажатие «Оплатить». Если ответ не дошёл (обрыв сети, таймаут), повторите запрос с тем же ключом: сервер вернёт тот же заказ и ту же ссылку, а не создаст второй. Ключ помнится сутки. Тот же ключ с другими полями — `422 idempotency_key_reused`.
- **Ошибки:** `409 plan_unavailable` — тариф больше недоступен, обновите `/plans`; `409 provider_unavailable` — способ оплаты выключен, обновите `/payment-methods`; `502 gateway_failed` — платёжная система не ответила, повторите позже или выберите другой способ; `503 purchases_disabled`.

**Статус:** `GET /orders/{id}` — тот же объект, но без `payment`.

| `status` | Значит |
|---|---|
| `pending` | ждёт оплаты |
| `completed` | оплачен; подписка — в `subscriptionId` (у продления — продлённая), её ссылка уже в `GET /subscriptions/{subscriptionId}` |
| `cancelled` | отменён. Если старую ссылку всё же оплатят, заказ станет `completed` |

Опрашивайте раз в 3–5 секунд, пока открыта оплата и сразу после возврата в приложение, — до `completed` или `cancelled`, но не дольше 15 минут. Дальше — при открытии экрана. Обычно подтверждение приходит за секунды, но бывает, что заказ становится `completed` через несколько минут.

**Новая ссылка:** `POST /orders/{id}/payment-link` — заказ с новым `payment`, шлюз тот же. Нужна, если ссылка истекла (у Platega — примерно через 15 минут, у Crypto Bot — по умолчанию через час) или окно оплаты закрыли.

- `409 order_not_pending` — заказ уже оплачен или отменён.
- `409 provider_unavailable` — этот способ оплаты выключили: отмените заказ и создайте новый.
- `409 renewal_option_unavailable` — заказ продления старше суток: его условия устарели, оформите продление заново (см. [«Продление»](#продление--subscriptionsidrenewals)).

**Отменить:** `POST /orders/{id}/cancel` — заказ со `status: "cancelled"`. Повторная отмена ошибкой не считается, оплаченный заказ — `409 order_not_pending`.

**Ссылка на оплату после отмены остаётся рабочей.** Если человек всё же оплатит её (например, форма оплаты была уже открыта), подписка будет выдана и заказ станет `completed`: деньги уже взяты. После отмены уберите ссылку с экрана, а при следующем открытии экрана перечитайте `/subscriptions`.

- Статус и отмена работают и при выключенных покупках (`purchasesEnabled: false`): заказ, начатый раньше, нужно довести до конца. Создать заказ и выпустить новую ссылку в это время нельзя (`503 purchases_disabled`).
- Чужой заказ — `404`.
- Пользователь с Telegram после оплаты получит и сообщение бота с подпиской, как при покупке в боте.

### После оплаты

Ссылку на оплату откройте во внешнем браузере или в Custom Tabs: на форме бывают переходы в банковские приложения (СБП), а встроенный WebView без доработки их не откроет.

После оплаты платёжная система вернёт человека на страницу `https://flintmain.ru/payment/app-return/{orderId}` — «Оплата в обработке» или «Оплата не завершена». Статус заказа страница не показывает, его приложение узнаёт само, опрашивая заказ.

- Кнопка «Вернуться в приложение» на странице появится, когда владелец сервиса задаст её адрес, например `flint://payment/{orderId}` (вместо `{orderId}` подставляется номер заказа). Схему выбирает команда приложения: регистрирует её на Android (intent-filter) и на ПК (протокол в системе) и сообщает владельцу. Пока адреса нет, страница просит вернуться в приложение вручную.
- Не полагайтесь только на эту страницу: человек может закрыть браузер, не дождавшись её. Когда приложение снова на экране, спросите статус заказа.

## Продление — /subscriptions/{id}/renewals

Продлить можно только активную подписку. Продление — тоже заказ: он создаётся своим эндпоинтом, а оплачивается, опрашивается, отменяется и получает новую ссылку так же, как покупка (см. [«Заказы»](#заказы--orders)). Ссылка подписки при продлении не меняется: сдвигается `expiresAt`, а лимит трафика может вырасти. Ссылка сменится, только если подписка успела истечь до оплаты (см. ниже).

**Варианты:** `GET /subscriptions/{id}/renewal-options`

```json
{
  "items": [
    {
      "days": 30,
      "price": { "amount": "150.00", "currency": "RUB" },
      "savings": null,
      "savingsPercent": null,
      "traffic": { "limitBytes": 1073741824000 }
    },
    {
      "days": 90,
      "price": { "amount": "400.00", "currency": "RUB" },
      "savings": { "amount": "50.00", "currency": "RUB" },
      "savingsPercent": 11,
      "traffic": { "limitBytes": 1073741824000 }
    }
  ]
}
```

- Вариантов может быть несколько: они идут по возрастанию `days`, и `days` не повторяется. Покажите все, например кнопками «30 дней — 150 ₽».
- **`savings`, `savingsPercent`** — выгода против самого короткого варианта списка: его цена за день, умноженная на `days`, минус `price`. Те же цифры, что на кнопке в боте; `null` — выгоды нет, бейдж не показывайте.
- **`traffic.limitBytes`** — лимит трафика подписки после оплаты: лимит её тарифа, но не ниже нынешнего `traffic.limitBytes` подписки; `null` — безлимит. У всех вариантов он одинаковый. Расход при продлении не обнуляется: если `traffic.usedBytes` подписки уже не меньше этого лимита, предупредите, что продление не вернёт доступ по трафику до обнуления расхода.
- Варианты подбирает сервер, как в боте. У тарифа могут быть свои варианты продления со своими ценами. Если их нет, подписка продлевается на срок своего тарифа по цене, за которую его купили, даже если тариф уже снят с продажи. У пробного периода без вариантов тарифа — сроки и цены из настроек сервера.
- Пустой `items` — продлить сейчас нельзя.
- Истёкшая подписка — `409 subscription_not_active`: предложите новую покупку. Чужая или скрытая — `404`.

**Заказать:** `POST /subscriptions/{id}/renewals`, заголовок `Idempotency-Key` — как у покупки:

```json
{ "days": 30, "provider": "platega" }
```

Ответ — `201 Created`, в `Location` — адрес заказа:

```json
{
  "id": "3a506446-f253-4d80-82ec-63e2e1a4e583",
  "type": "renewal",
  "status": "pending",
  "plan": { "id": "5", "name": "1 месяц" },
  "days": 30,
  "provider": "platega",
  "subscriptionId": null,
  "payment": {
    "url": "https://pay.platega.io/…",
    "amount": { "amount": "150.00", "currency": "RUB" },
    "displayAmount": null
  }
}
```

- `days` берите из `renewal-options`, `provider` — из `/payment-methods`. `plan` — тариф продлеваемой подписки.
- Заказ фиксирует срок и сумму при оформлении. Если варианты или цены на сервере потом поменяются, этот заказ всё равно продлит подписку на свой срок, а новая ссылка на оплату выставится на ту же сумму.
- Условия заказа держатся сутки. Позже `POST /orders/{id}/payment-link` для такого заказа может ответить `409 renewal_option_unavailable`: перечитайте `renewal-options` и оформите продление заново. Оплата по ссылке, выданной раньше, заказ всё равно проведёт.
- После оплаты `GET /orders/{id}` вернёт `completed`, а в `subscriptionId` — продлённую подписку. Перечитайте её (`GET /subscriptions/{subscriptionId}`), чтобы показать новый `expiresAt` и `traffic.limitBytes`.
- **Ошибки:** `409 renewal_option_unavailable` — на этот срок продлить нельзя, обновите варианты; `409 subscription_not_active` — подписка уже истекла; `409 provider_unavailable`, `502 gateway_failed`, `503 purchases_disabled` — как у покупки.
- **Если подписка истечёт раньше, чем придёт оплата,** оплата всё равно её продлит: подписка снова станет `active` на оплаченный срок, считая от момента оплаты. Но **ссылка подписки сменится**: на VPN-сервере создаётся новый пользователь. Перечитайте подписку и замените ссылку в VPN-ядре. Новую ссылку на оплату для такого заказа тоже можно получить.
- Лимит у продлений общий с заказами.

## Пробный период — /subscriptions/trial

Один раз на пользователя, как в боте. Кнопку «Попробовать бесплатно» показывайте, только если в `/me` пришло `trialAvailable: true`. Срок пробного периода — `config.trial.days`.

`POST /subscriptions/trial`, без тела. Ответ — `201 Created`, в `Location` — адрес подписки. В теле — сама подписка, уже активная и со ссылкой, в том же виде, что в [`GET /subscriptions/{id}`](#подписки--subscriptions):

```json
{
  "id": "b349a009-8ca9-41cd-b3bb-04e21892409f",
  "status": "active",
  "plan": { "id": "1", "name": "Тестовая подписка" },
  "startedAt": "2026-09-27T09:35:09Z",
  "expiresAt": "2026-09-30T09:35:09Z",
  "subscriptionUrl": "https://…/sub/…",
  "traffic": { "usedBytes": 0, "limitBytes": 1073741824000, "updatedAt": null, "limitReached": false }
}
```

- `traffic.limitBytes` — лимит пробного периода. После оплаченного продления подписка получает обычный лимит, но не ниже прежнего.
- **Режим сервера** — `config.trial.mode`. При `everyone` пробный период доступен всем. При `telegram_only` — только аккаунтам с Telegram, а аккаунт, зарегистрированный по email, получит `403 trial_requires_telegram`. Режим переключает администратор, поэтому показ кнопки решайте по `trialAvailable`.
- **Ошибки:**
  - `409 trial_used` — пробный период уже получен, в боте или в приложении;
  - `403 trial_requires_telegram` — см. режим выше;
  - `503 trial_unavailable` — выдать не удалось, повторите позже. Пробный период при этом не расходуется.
- Если ответ не дошёл и повтор вернул `409 trial_used`, первый запрос успел выдать подписку: перечитайте `/subscriptions`.
- Пользователь с Telegram получит и сообщение бота с подпиской и QR-кодом, как при пробном периоде из бота.
- Пробный период не зависит от покупок (`purchasesEnabled`). Лимит у него общий с заказами.

## Рефералка — /referrals

У каждого пользователя свой код. Друг указывает его при регистрации (`referralCode` в [`/auth/register`](#вход-по-email)) или позже в `POST /referrals/apply`. Когда друг покупает подписку, пригласивший получает бонусные дни к своей активной подписке, как в боте. Если активной подписки в этот момент нет, бонус за эту покупку пропадает. Продления и пробный период бонуса не дают.

`GET /referrals`:

```json
{
  "code": "IXP06QB6",
  "invitedCount": 2,
  "bonusDays": 5,
  "referrer": { "name": "Иван" },
  "terms": { "bonusPercent": 10.0, "minPurchaseDays": 1, "maxBonusDays": 30 },
  "rewards": [
    { "days": 2, "awardedAt": "2026-09-20T10:15:00Z", "friendName": null },
    { "days": 3, "awardedAt": "2026-09-12T08:00:00Z", "friendName": "Пётр" }
  ]
}
```

- `code` — код пользователя, им делятся с друзьями. Он же работает в боте: код можно просто отправить боту сообщением.
- `invitedCount` и `bonusDays` — те же цифры, что в «Моей рефералке» в боте. `bonusDays` — дни, добавленные к подпискам пользователя; пропавшие бонусы в него не входят.
- `referrer` — кто пригласил самого пользователя; `null` — никто. `name` — имя из Telegram, у аккаунта приложения его нет (`null`).
- `terms` — условия: пригласивший получает `bonusPercent` % от срока подписки, купленной другом, но не больше `maxBonusDays` дней за покупку. Покупка короче `minPurchaseDays` дней бонуса не даёт.
- `rewards` — последние 50 начислений, добавленных к подписке, новые первыми; пропавших бонусов в списке нет. `awardedAt` — когда дни добавлены, `friendName` — имя друга из Telegram или `null`.
- Если в `/config` `referralsEnabled: false`, бонусы не начисляются — спрячьте экран рефералки.

**Ввести код друга:** `POST /referrals/apply`:

```json
{ "code": "AB12CD34" }
```

- Ответ — `200` и обновлённая рефералка, как в `GET /referrals`. Регистр и пробелы по краям неважны.
- Пригласившего можно сменить, введя другой код, — как в боте. Тот же код повторно ничего не меняет.
- **Ошибки:** `400 invalid_referral_code` — такого кода нет; `400 own_referral_code` — это собственный код пользователя; `400 validation_failed` — код пустой.
- Лимит — как у входа.

## Обновление приложения — /app/update

`GET /app/update?platform=android&version=1.2.0` — есть ли новая версия приложения. С токеном; работает и в техработы: обновление может понадобиться как раз во время них.

```json
{
  "updateAvailable": true,
  "required": false,
  "minVersion": "1.1.0",
  "latest": {
    "version": "1.3.0",
    "versionCode": 130,
    "publishedAt": "2026-10-06T09:12:44Z",
    "notes": "Быстрее выбирается локация.\nИсправлено подключение на Android 14.",
    "url": "https://flintmain.ru/api/v1/app/files/5f0c1d2e3f4a5b6c7d8e9f0a1b2c3d4e/flint-android-1.3.0.apk?u=12345&expires=1759768364&sig=Xq3…",
    "path": "/api/v1/app/files/5f0c1d2e3f4a5b6c7d8e9f0a1b2c3d4e/flint-android-1.3.0.apk?u=12345&expires=1759768364&sig=Xq3…",
    "urlExpiresAt": "2026-10-06T15:12:44Z",
    "fileName": "flint-android-1.3.0.apk",
    "size": 48211337,
    "sha256": "3a7bd3e2360a3d29eea436fcfb7e44c735d117c42d1c1835420b6b9942dd4f1b"
  }
}
```

| Параметр | Что передать |
|---|---|
| `platform` | `android`, `windows`, `macos`, `linux`, `ios` |
| `version` | версия приложения, как в `X-Client`: `1.2.0`. Сервер берёт её числовое начало: `1.2.0-beta` и `1.2.0 (45)` — это `1.2.0` |

Неверные значения — `400 validation_failed` с ошибками у `platform` и `version`.

- `latest` — сборка, которую сейчас раздаёт сервер. Приходит, даже если обновляться не нужно. `null` — раздачи нет; на iOS — всегда.
- `updateAvailable` — `latest.version` выше присланной версии. Версии сравниваются по числам: `1.10` выше `1.9`, `1.3` и `1.3.0` — одна версия.
- `required` — присланная версия ниже `minVersion`: обновление обязательное.
- `minVersion` — ниже неё приложение обязано обновиться; `null` — не задана.
- `latest.versionCode` — только у Android, из APK; у других платформ `null`.
- `latest.notes` — «Что нового», простой текст с переводами строк `\n`; `null` — описания нет.
- `latest.url` — ссылка на файл, действует до `urlExpiresAt` (6 часов). Она без токена: её можно отдать системному загрузчику. `path` — та же ссылка без домена: если приложение сейчас ходит через запасной домен, качайте с него.
- `latest.size` и `latest.sha256` — размер файла в байтах и его SHA-256 (hex, нижний регистр).

### Когда проверять и что показывать

- При запуске после входа и раз в 12 часов, пока приложение открыто. Не чаще раза в час.
- `required: true` — экран обновления без кнопки «Позже»: пользоваться приложением можно только после обновления. Оставьте на экране выход из аккаунта и ссылку на поддержку.
- `updateAvailable: true` — окно с `notes` и кнопками «Обновить» и «Позже». «Позже» прячет окно до завтра или до новой версии (`latest.version`).
- Оба `false` — ничего не показывать.

### Скачивание

- Качайте по `url` — или по `path` на текущем домене — до `urlExpiresAt`. Ссылка истекла — запросите `/app/update` заново.
- Докачка есть: `Range`, `If-Range`, `ETag` (это `sha256` в кавычках), `If-None-Match`. `HEAD` отдаёт заголовки без файла.
- Перед установкой сверьте размер файла с `size`, а его SHA-256 — с `sha256`. Не совпало — удалите файл и скачайте заново.
- `403 download_link_invalid` — ссылка неверна, истекла или эту сборку больше не раздают: например, администратор откатил версию. Запросите `/app/update` заново, не чаще раза в минуту.
- `404 not_found` — файла нет на сервере: повторите проверку позже.
- `403 account_banned` — экран блокировки.
- Файл качается без входа, поэтому на него действует лимит запросов без входа — 300 в минуту с IP.

### Android

- В манифесте нужно разрешение `REQUEST_INSTALL_PACKAGES`, а у пользователя — «Установка неизвестных приложений» для вашего приложения. Проверьте `packageManager.canRequestPackageInstalls()` и, если нельзя, откройте `Settings.ACTION_MANAGE_UNKNOWN_APP_SOURCES`.
- До скачивания сверьте `latest.versionCode` со своим: если он не выше, не предлагайте обновление — Android его всё равно не поставит.
- Качать удобно через `DownloadManager`: ему подходит `url` без токена, и он сам докачивает.
- Устанавливайте через `PackageInstaller` (сессию) или `ACTION_VIEW` с `content://`-адресом от `FileProvider`. Система спросит подтверждение у пользователя.
- Android ставит обновление, только если у него та же подпись, а `versionCode` выше установленного. Сервер другие и не раздаёт.

### Windows

- Файл — установщик `.exe`. Скачайте его во временную папку (`%TEMP%`) и сверьте `size` и `sha256`.
- Запустите установщик и закройте приложение, иначе установщик не заменит его файлы. Windows спросит права администратора.
- После установки приложение запускается уже новой версией.

### Защита от петли

Если сервер снова предлагает сборку с тем же `sha256`, который приложение уже скачивало и запускало, не предлагайте её до следующего запуска приложения и запишите это в лог. Так бывает, когда версия внутри сборки не совпала с заявленной на сервере: без этой защиты приложение предлагало бы обновиться снова и снова.

### Сервер без проверки обновлений

`404 not_found` на сам `/app/update` значит, что этот сервер обновления не раздаёт — например, после отката сервера на прошлую версию. Пропустите проверку молча.

## Поддержка — /support

Обращения в поддержку: пользователь пишет из приложения, поддержка отвечает из админки. Нужен вход. Блокировка и техработы действуют как везде (`403 account_banned`, `503 maintenance`). Кто не может войти, пишет в Telegram по ссылке `links.support` из [`/config`](#конфигурация--get-config) — её оставьте на экране входа и на экране блокировки.

### Темы обращения

`GET /support/categories`:

```json
{
  "items": [
    { "id": "connection", "title": "Подключение" },
    { "id": "payment", "title": "Оплата и подписка" },
    { "id": "account", "title": "Аккаунт и вход" },
    { "id": "other", "title": "Другое" }
  ]
}
```

Список может меняться — берите его с сервера, а не из сборки.

### Новое обращение

`POST /support/tickets` с заголовком `Idempotency-Key`:

```json
{ "category": "connection", "subject": "Не подключается", "text": "С утра не работает ни одна локация." }
```

Ответ — `201` и обращение с перепиской, в том же виде, что [`GET /support/tickets/{id}`](#обращение-и-переписка).

| Поле | Обязательно | Ограничения |
|---|---|---|
| `category` | да | `id` из `/support/categories` |
| `subject` | да | 1–100 символов, одна строка |
| `text` | да | 1–4000 символов |

- Пробелы по краям обрезаются, переводы строк в тексте сохраняются. Неверные поля — `400 validation_failed` с ошибкой у поля.
- **`Idempotency-Key`** — как у заказов: новый ключ на каждое обращение. Повтор с тем же ключом в течение суток вернёт то же обращение, а не создаст второе; тот же ключ с другими полями — `422 idempotency_key_reused`.
- Устройство (платформа, модель, версии) сервер берёт из сессии — передавать его не нужно.
- `409 too_many_open_tickets` — у пользователя уже 3 открытых обращения: покажите `detail` и откройте список обращений.

### Обращение и переписка

`GET /support/tickets/{id}`:

```json
{
  "id": "1001",
  "category": "connection",
  "subject": "Не подключается",
  "status": "waiting_for_user",
  "createdAt": "2026-10-08T09:12:40Z",
  "lastMessageAt": "2026-10-08T09:30:02Z",
  "lastMessage": { "author": "support", "text": "Здравствуйте! Обновите подписку в приложении…", "createdAt": "2026-10-08T09:30:02Z" },
  "unreadCount": 1,
  "closedAt": null,
  "closedBy": null,
  "rating": null,
  "canRate": false,
  "messages": [
    { "id": "15", "author": "user", "authorName": null, "text": "С утра не работает ни одна локация.", "createdAt": "2026-10-08T09:12:40Z" },
    { "id": "18", "author": "support", "authorName": null, "text": "Здравствуйте! Обновите подписку в приложении и попробуйте снова.", "createdAt": "2026-10-08T09:30:02Z" }
  ]
}
```

| `status` | Что показать |
|---|---|
| `new` | «Новое» — ждёт поддержки |
| `in_progress` | «В работе» — поддержка взяла обращение |
| `waiting_for_user` | «Есть ответ» — поддержка ответила и ждёт пользователя |
| `waiting_for_support` | «Ждём ответа поддержки» |
| `closed` | «Закрыто» |

- **`id`** — номер обращения: показывайте «Обращение №1001».
- **`messages`** — по порядку, только сообщения пользователя и поддержки. `author` — `user` или `support`. `authorName` — имя сотрудника, если он решил его показывать; `null` — подпишите «Поддержка».
- **`?afterMessageId=18`** — только сообщения новее `18`: так опрашивайте открытое обращение, не перекачивая всю переписку. Статус и счётчики в ответе — текущие.
- **`unreadCount`** — ответов поддержки после отметки «прочитано». После показа переписки отправьте `POST /support/tickets/{id}/read` с `{"upToMessageId": "18"}` — id последнего показанного сообщения → `204`. Отметка только растёт и не уходит дальше последнего сообщения: ответ, пришедший после неё, останется непрочитанным.
- **`closedBy`** — кто закрыл: `user`, `support` или `system` (закрыто автоматически). У открытого — `null`.
- **`rating`** — `{resolved, score, comment, ratedAt}` или `null`. **`canRate: true`** — обращение закрыто и ещё не оценено: покажите «Оцените работу поддержки».
- Чужое или несуществующее обращение — `404`.

### Список обращений

`GET /support/tickets` → `{"items": [обращение без messages], "unreadTickets": 1}`. Открытые выше, дальше по последнему сообщению, не больше 100. `?status=open` — только открытые, `?status=closed` — только закрытые, по умолчанию `all`. `lastMessage.text` — начало последнего сообщения одной строкой, до 200 символов. `unreadTickets` — сколько обращений с непрочитанными ответами: для значка «Поддержка».

### Написать в обращение

`POST /support/tickets/{id}/messages` с `{"text": "…"}` и `Idempotency-Key` → `201` и сообщение (`id`, `author`, `authorName`, `text`, `createdAt`). Ключ — новый на каждое сообщение: повтор после обрыва связи не задвоит его.

- `409 ticket_closed` — обращение закрыто: обновите его и предложите создать новое.
- `409 ticket_message_limit` — в обращении уже 300 сообщений пользователя: предложите создать новое.
- Ответ пользователя на `waiting_for_user` переводит обращение в `waiting_for_support`.

### Закрыть и оценить

- `POST /support/tickets/{id}/close` → `200` и обращение без `messages`. Повтор на закрытом — тот же ответ. Закрыть может и пользователь, и поддержка.
- Закрытое обращение снова не открывается: с новым вопросом — новое обращение.
- **Автозакрытие:** если поддержка ответила, а пользователь не пишет несколько дней (по умолчанию 7, срок задаёт поддержка), обращение закрывается само — `closedBy: "system"`. Оценить его можно так же, как закрытое вручную.
- `POST /support/tickets/{id}/rating` с `{"resolved": true, "score": 4, "comment": "Спасибо"}` → `200` и обращение. `resolved` — решён ли вопрос, `score` — от 1 до 5, `comment` — необязателен, до 1000 символов. Оценить можно один раз: `409 ticket_already_rated`; открытое — `409 ticket_not_closed`.

### Как обновлять

- **Экран обращения:** `GET /support/tickets/{id}?afterMessageId=<последний>` раз в 10–15 секунд, пока экран открыт и обращение не закрыто.
- **Список и значок:** `GET /support/tickets` при открытии экрана и при возврате в приложение.
- **В фоне не опрашивайте:** push пока нет.
- **Пользователю с Telegram** бот коротко пишет, что поддержка ответила или закрыла обращение (не чаще раза в 10 минут на обращение), — без текста ответа, с отсылкой в приложение. Аккаунты без Telegram узнают об ответе только в приложении.

Описание со всеми полями открывается на сервере по адресу `/swagger` — только администратору. Файл для генерации клиента — `/swagger/v1/swagger.json`, его выгружает и передаёт владелец сервиса.
